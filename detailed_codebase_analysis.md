# Detailed Codebase Analysis Report

This report provides an in-depth summary of every single file in the Aloo Type codebase. It is designed to be an exhaustive breakdown of the architectural roles of all files within the repository.

## Configuration & Root Files

- **`.gitignore`**: Defines files and directories that Git should not track. This includes dependencies (`node_modules`), build outputs (`.next`), environment variables (`.env`), and test reports (`playwright-report`, `test-results`).
- **`components.json`**: The configuration file for `shadcn/ui`. It specifies that the project uses TypeScript, Tailwind CSS, and sets the aliases (like `@/components`) for where newly generated UI components should be placed.
- **`CONTRIBUTING.md`**: A markdown file providing guidelines for developers who want to contribute to the project. It likely includes steps for setting up the dev environment, coding standards, and how to submit pull requests.
- **`eslint.config.mjs`**: The configuration file for ESLint (using the new flat config format). It defines the linting rules for TypeScript and React to ensure code quality and prevent common errors.
- **`next-env.d.ts`**: An auto-generated TypeScript declarations file by Next.js. It ensures the TypeScript compiler knows about Next.js specific types and image imports.
- **`next.config.ts`**: The core configuration for the Next.js framework. It defines settings like React strict mode, image domains, webpack customizations, and experimental features (like Turbo or specific server actions).
- **`package-lock.json`**: The exact dependency tree generated by npm. It locks the versions of all dependencies and sub-dependencies to ensure reproducible builds across different environments.
- **`package.json`**: The manifest file for the project. It lists all the top-level npm dependencies (like `react`, `next`, `zustand`, `tailwindcss`), metadata about the project, and npm scripts (e.g., `npm run dev`, `npm run build`, `npm run test`).
- **`playwright.config.ts`**: The configuration file for the Playwright E2E testing framework. It sets the test directory (`e2e/`), the browsers to test against (Chromium, Firefox, WebKit), local dev server settings, and timeout limits.
- **`postcss.config.mjs`**: Configuration for PostCSS. It tells the build system to use `tailwindcss` and `autoprefixer` plugins when processing CSS files.
- **`README.md`**: The main entry point for anyone looking at the repository. It contains the project description, features, setup instructions, and architecture overview for Aloo Type.
- **`tailwind.config.ts`**: The Tailwind CSS configuration file. It extends the default theme with custom colors (likely specific to the Aloo Type brand), font families, and animation keyframes. It also includes safelists for dynamic class generation, crucial for the typing heatmap colors.
- **`tsconfig.json`**: The TypeScript compiler options. It defines how strictly the code should be type-checked, what module resolution strategy to use, and includes path aliases like `@/*` mapping to `./src/*`.
- **`tsconfig.tsbuildinfo`**: An auto-generated binary file used by TypeScript to cache compilation information, speeding up subsequent builds.
- **`vitest.config.ts`**: Configuration for Vitest, the unit testing framework used here. It sets up the test environment (like `jsdom` for React components) and points to the global test setup file.
- **`.vscode/settings.json`**: Workspace settings for Visual Studio Code. It enforces formatting rules on save, sets the default formatter (e.g., Prettier), and tailors the IDE experience for this specific project.
- **`.github/workflows/ci.yml`**: The CI/CD pipeline definition for GitHub Actions. It specifies the steps to run automatically on push/PR, typically including installing dependencies, running ESLint, Vitest, and Playwright tests.

## Documentation (`docs/`)

- **`docs/ALGORITHMS.md`**: A detailed technical explanation of the math and algorithms used in Aloo Type. This includes how Gross and Net WPM (Words Per Minute) are calculated, how the moving average for live WPM works, and the formulas behind accuracy metrics.
- **`docs/DATA_SCHEMA.md`**: Outlines the shape of the data stored for users. It documents the interfaces for typing sessions, user profiles, historical statistics, and how they map to the underlying storage (IndexedDB or API).
- **`docs/VALIDATION.md`**: Documents the strict validation and anti-cheat rules implemented. It details the server-side and client-side checks for impossible timestamps, typing speeds (e.g., > 300 WPM limits), and payload sanitization to prevent leaderboard hacking.
- **`docs/WEAKNESS_DETECTOR_REFACTOR.md`**: A design document or post-mortem detailing the architectural shift of moving the N-gram based weakness detection from the main thread into a Web Worker to eliminate UI blocking and hydration issues.

## End-to-End Tests (`e2e/`)

- **`e2e/01-app-foundation.spec.ts`**: Playwright test asserting that the base application loads correctly. It checks for the presence of the main layout, navigation bar, and footer, ensuring there are no 500 errors on load.
- **`e2e/02-typing-engine.spec.ts`**: Critical tests for the core typing interaction. It simulates user keystrokes and asserts that correct characters are highlighted, errors are tracked, the caret moves appropriately, and the final stats screen appears.
- **`e2e/03-lessons.spec.ts`**: Tests the structured lesson progression flow. It verifies that a user can start a lesson, complete it, and that the next lesson unlocks successfully in the UI.
- **`e2e/04-dashboard.spec.ts`**: Tests the user dashboard. It asserts that after completing a typing test, the user's recent scores, WPM trends, and heatmaps correctly render on their profile dashboard.
- **`e2e/05-gamification.spec.ts`**: Tests the achievement and combo systems. It simulates a flawless typing streak to verify the combo multiplier appears, and checks if unlocking specific milestones triggers the achievement toast notifications.
- **`e2e/06-weakness-detection.spec.ts`**: Tests the integration with the ML weakness detector. It intentionally types specific bigrams (like "th" or "er") slowly to assert that the system correctly identifies them as weaknesses in the post-test analysis.
- **`e2e/07-persistence.spec.ts` & `e2e/persistence.spec.ts`**: Tests data saving mechanisms. It completes a test, reloads the page, and asserts that the user's progress, settings, and high scores are retained across sessions.
- **`e2e/08-sync.spec.ts`**: Tests the synchronization features, potentially mocking an offline state, completing a test, coming back online, and asserting the data syncs to the backend server.
- **`e2e/09-accessibility.spec.ts`**: Automated accessibility checks. It uses axe-core or Playwright's built-in tools to ensure the typing area can receive focus, ARIA labels are present, and the color contrast is adequate.
- **`e2e/10-performance.spec.ts`**: Specialized tests that measure the responsiveness of the typing input. It likely simulates rapid typing (150+ WPM) and asserts that the UI does not drop frames or lag significantly.
- **`e2e/helpers.ts`**: A collection of utility functions shared across the E2E tests, such as `simulateTyping(page, text)`, `loginUser(page)`, or `clearStorage()`, to keep the test files clean and DRY.
- **`e2e/offline.spec.ts`**: Simulates the browser going offline (via Playwright's network intercepts) and verifies that the PWA service worker successfully serves the cached app shell and allows offline typing.
- **`e2e/qa-typing-audit.spec.ts`**: A rigorous, stress-testing script designed to uncover edge cases in the typing engine, such as mashing keys, rapidly pasting text, or interrupting the test with window blurring.
- **`e2e/typing-flow.spec.ts`**: A comprehensive end-to-end integration test tracing a user's entire journey from the homepage, starting a test, completing it, and viewing the detailed stats page.

## Hooks (`src/hooks/`)

- **`src/hooks/use-confetti.ts`**: A custom hook that wraps a confetti library (like `canvas-confetti`). It provides an easy `triggerConfetti()` function to use in components when celebrating milestones.
- **`src/hooks/use-sound.ts`**: A custom hook for managing audio. It preloads typing sounds and provides functions to play specific sound bytes (key press, error buzzer, test complete) with low latency.
- **`src/hooks/use-typing-controller.ts`**: The most critical hook in the app. It acts as the orchestrator for a typing session. It attaches keyboard event listeners, computes correctness, calculates live WPM, manages the timer, and dispatches state updates to the Zustand store.

## Core Library & Utilities (`src/lib/`)

- **`src/lib/achievements.ts`**: A configuration and logic file defining the rules for all unlockable achievements (e.g., what conditions trigger "Speed Demon").
- **`src/lib/anti-cheat.ts`**: Contains functions used to detect suspicious behavior, such as analyzing the variance between keystrokes to detect macros, or verifying that the typed string mathematically aligns with the reported time.
- **`src/lib/daily-challenges.ts`**: Logic for generating the daily and weekly challenges based on a seed (like the current date), ensuring all users get the same challenge on a given day.
- **`src/lib/keyboard-data.ts` & `src/lib/keyboard-layouts.ts` & `src/lib/layouts.ts`**: These files define the physical mappings of different keyboard layouts. They provide the row/column coordinates for keys on QWERTY, Dvorak, Colemak, etc., which are necessary for the visual keyboard and heatmap components.
- **`src/lib/lessons.ts`**: Utility functions for retrieving lesson content, managing lesson prerequisites, and parsing the lesson data structures.
- **`src/lib/ngram-analyzer.ts`**: The mathematical logic for analyzing typing sequences. It breaks down typed text into unigrams, bigrams, and trigrams, comparing expected vs. actual times to identify the specific character combinations a user struggles with most.
- **`src/lib/practice-texts.ts`**: An embedded database or corpus of text snippets, quotes, and standard word lists used for the general practice modes.
- **`src/lib/sound-engine.ts`**: A more robust, likely Web Audio API-based, engine for handling concurrent keystroke sounds efficiently without audio clipping when typing very fast.
- **`src/lib/utils.ts`**: A collection of generic, highly reusable utility functions. Notably, it almost certainly includes the `cn` function (combining `clsx` and `tailwind-merge`) used heavily by shadcn components.
- **`src/lib/locales/en.ts`**: The English localization dictionary. It stores static strings used across the app, enabling easy internationalization (i18n) in the future.
- **`src/lib/storage/db.ts`**: A wrapper around IndexedDB (possibly using a library like `idb`). It provides an asynchronous, reliable API for saving large amounts of offline typing history and statistics that wouldn't fit in localStorage.

## State Management (`src/stores/`)

These files define the global state using Zustand.
- **`src/stores/achievement-store.ts`**: Maintains the list of unlocked achievements and coordinates with local storage to persist them.
- **`src/stores/analytics-store.ts`**: Holds the aggregated historical data, such as moving WPM averages, error frequencies, and heatmap data across all completed sessions.
- **`src/stores/challenge-store.ts`**: Manages the user's progress on active daily and weekly challenges.
- **`src/stores/diagnostic-store.ts`**: Holds state specifically for the initial onboarding diagnostic test (is it active, what was the result).
- **`src/stores/game-store.ts`**: Manages the transient gamification state during a session, like the current combo meter, streak count, and temporary score multipliers.
- **`src/stores/leaderboard-store.ts`**: Caches leaderboard data fetched from the API to display the top typists globally or among friends.
- **`src/stores/progress-store.ts`**: Tracks which lessons are locked, unlocked, and completed, along with the user's high score for each specific lesson module.
- **`src/stores/settings-store.ts`**: Manages user preferences like UI theme, selected keyboard layout, sound volume, and caret style. It heavily syncs with localStorage.
- **`src/stores/typing-store.ts`**: The most volatile store. It tracks the millisecond-by-millisecond state of an active typing test: the exact position of the caret, the array of correctly and incorrectly typed characters, and the active timer state.
- **`src/stores/user-store.ts`**: Manages the overall user profile, authentication token (if any), and broad metadata like join date and display name.

## Web Workers (`src/workers/`)

- **`src/workers/ml-worker-instance.ts`**: A singleton class or function that instantiates the Web Worker. It ensures that only one worker thread is spawned and provides the mechanism to send and receive messages from it.
- **`src/workers/ml.worker.ts`**: The actual script executing in the background thread. It receives heavy arrays of typing data, runs the N-gram analysis, calculates weakness thresholds, and returns the processed results to the main thread, keeping the UI at 60 FPS.
- **`src/workers/ml.worker.test.ts`**: Vitest unit tests specifically verifying the math and logic inside the worker script.
